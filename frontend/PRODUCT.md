# CareerLens

<!-- impeccable:product-schema 1 -->

## Platform

web

## Product Purpose

프로젝트 2는 이력서와 채용공고를 연결해 모의지원 분석과 보고서를 제공한다. 실제 기업에 지원서를 보내는 서비스가 아니다.

## Users

사용자는 이력서 준비, 희망 직무와 공고 선택, 인증, 모의지원 분석, 보고서 조회를 진행한다. 운영 대시보드는 로그인 없이 읽기 전용으로 열 수 있다. 개인 이력서·보고서와 쓰기 작업의 인증·소유권 확인은 유지한다.

## Capabilities and Constraints

프론트는 기존 Flask와 브라우저 JavaScript를 유지하며 FastAPI와 한 서비스에서 배포한다. 2026-10-13 개인 포트폴리오 요청에 따라 동시 분석·Redis 상태 공유·운영 지표 연결을 위한 백엔드 수정과 개인 GitHub 공개·Render 배포를 포함한다. 대시보드와 이용 흐름은 로그인 없이 공개하며 개인 이력서·보고서 원문은 소유자 인증을 유지한다. 실제 점수와 진행률은 서버 응답만 사용하며 미제공 값은 미수집으로 표시한다.

## Operating Context

2026-10-13 사용자는 개인 GitHub와 Render로 배포하는 AI 활용 프론트엔드 포트폴리오를 요청했다. 첫 화면부터 프론트엔드 구현과 개인 배포를 알리고, 기존 팀 백엔드와 개인의 수정 범위를 구분한다. 페이지마다 모든 주요 기능 안내를 동시에 표시하고 어디든 클릭하면 닫으며 다음 페이지에서 다시 안내한다. 로그인한 회원의 랜덤 이력서는 프로젝트의 합성 Markdown 원본을 사용한다.

가장 최근 요청에 따라 채용 담당자와 방문자는 대시보드·이용 흐름을 로그인 없이 읽기 전용으로 체험한다. 일반 사용자 접근을 막는 이전 요구는 이 공개 체험 요청으로 대체되었다. 공개 화면에는 개인 이력서·점수·보고서 원문을 제공하지 않는다. 결과 확인은 이용 흐름만 별도 팝업으로 열고 원래 창의 분석 로딩·결과 화면을 유지한다. 여러 사용자의 분석은 동시에 처리하고 Redis의 실제 실행 상태로 관찰한다. 대시보드는 기존 실행 보고서에서 추출한 허용 지표와 배포에서 생성된 PostgreSQL 기록을 함께 표시한다. 모니터링 카드는 변경 전 개수에서 12개를 통합·축소하고, 서버가 관측하지 않은 내부 동작을 실제로 수집한 것처럼 표현하지 않는다.

## Brand Commitments

기존 서비스는 흰색·파란색 화면과 CareerLens 로고를 유지한다. 새 관찰 화면에 한해 사용자가 제공한 어두운 네트워크 모션 레퍼런스를 적용하며, 사용자의 요청에 따라 같은 흐름을 밝은 모드로도 선택해 볼 수 있다. 기존 주요 메뉴와 실제 분석 동작을 보존한다.

## Product Principles

- 실행 결과와 시연 데이터를 명확히 구분한다.
- 이용 흐름은 단계와 상태로 표현하며 개인정보나 자격증명을 복제하지 않는다.
- 관찰 화면은 서비스 사용을 방해하지 않는 별도 화면으로 연다.
- 관측되지 않은 내부 동작을 애니메이션으로 사실처럼 만들지 않는다.
