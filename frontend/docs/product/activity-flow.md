# 개인 포트폴리오 이용 흐름

2026-10-13 개인 Render 배포의 공개 모니터링 기준이다. 이전의 회원 전용·브라우저 탭별 관찰 요구를 대체한다.

## 연결과 관찰 범위

- 기본 ‘실시간 · 전체 이용’은 여러 사용자의 브라우저 동작과 분석 실행 상태를 함께 조회한다. 화면 진입·이력서·공고·로그인·API 요청은 브라우저 관측이며, 워커의 분석 단계는 서버 기록이다. 두 종류를 별도 대상으로 표시하고 상태를 섞지 않는다.
- 브라우저는 허용된 기능명·상태·시간만 중앙 수집기로 전송한다. Redis가 이를 짧게 보관하고, 이용 흐름 화면은 약 1.5초 간격으로 최신 상태를 조회한다. 연결 확인 신호가 과거 동작을 새 활동으로 만들지 않는다.
- 자동 추적은 새 작업을 따라간다. 상세 대상을 고정하면 다른 사용자의 이벤트가 지도를 바꾸지 않는다. 전체 목록에는 여러 대상이 함께 표시된다.
- ‘이 브라우저만’은 같은 출처의 브라우저 채널로 관찰한다. 작업 창에서 연 팝업은 해당 창을 보고, 직접 열린 이용 흐름 화면은 같은 브라우저의 작업 창들을 관찰한다.
- Redis 장애나 조회 실패는 연결 상태에 표시한다. 과거 기록을 현재 실행으로 표시하거나, 누락된 단계를 완료로 추정하지 않는다.

## 표시와 모션

기존 41개를 29개로 통합한 수정에서 다시 기본 화면을 7개 요약 단계로 정리했다. 접속·계정, 이력서 준비, 직무·공고, 분석 요청, AI 분석, 보고서, 운영·보관이다. 이전의 약 12개 감소 요구는 41→29에서 이미 충족했고, 이번에는 29개 관측 항목을 접힌 실시간 상태 지도에 보존한다. 원시 기능을 삭제해 숫자를 맞추지 않는다.

요약 카드를 누르면 사이드바가 있는 세부 흐름 창이 열린다. 하위 카드 선택으로 같은 창 안에서 더 깊이 들어가며 탐색 위치·이전 단계·닫기로 복귀한다. 분석의 평가 영역과 각 기준은 생성된 소스 구조에서 가져온다. 직전·직후 연결, 전체 이전·이후 경로, 시작·끝, 전체 구성원과 코드 근거를 탐색할 수 있다. 연결 유형은 처리 순서·조건 분기·정적 호출·하위 구성·응답 형식으로 구분하며, 구성이나 함수 호출을 실제 실행 순서로 단정하지 않는다.

7개 요약 카드에는 실제 관측 이벤트를 집계한다. 기존 29개 관측 지도는 수집 허용 항목에 한정되며 연결선은 생성된 소스 관계를 사용한다. 최초 기록·복구·중복 조회에는 과거 애니메이션을 재생하지 않고, 새로 수신한 동작과 상태 변경만 강조한다. 실제 수집된 응답 시간·진행 상태만 표시한다.

세부 창의 시연은 선택 카드별 가상 입력·처리·출력을 제공한다. 성공·실패 예시, 재생·일시정지·초기화를 제공하며 선택 전환·뒤로 이동·닫기는 이전 타이머를 무효화한다. 이 시연은 실제 API, 유료 모델, 인증, 계정 저장소나 중앙 수집기를 호출하지 않는다. 기존 전체 경우별 시연도 접힌 보조 영역에서 유지한다. 페이지 기능 안내는 새 기능 위치에 개별 말풍선으로 표시한다.

사용자 행동 시연은 로그인·로그아웃·취소·결과 잠금 등 기능별 실제 의미에 맞는 별도 입력과 상태 변화를 사용한다. 평가 기준은 현재 생성된 이름·영역·가중치·평가 규칙과 예시 작성 당시 계약이 모두 일치할 때만 해당 기준의 가상 점수와 판단 근거를 보여준다. 신규 기준이나 변경된 규칙은 과거 예시를 재사용하지 않고 현재 소스 계약의 구조 시연으로 전환한다. API·내부 함수·스키마 카드는 요청 방식·경로·필드·호출 관계 등의 현재 구조를 보여주며 HTTP 성공 응답이나 실제 함수 반환값을 임의로 만들지 않는다.

기존 어두운 관찰 화면과 밝은 모드, Pretendard 계열 글꼴, 청록색 상태 강조를 유지한다. 작은 화면에서는 요약을 2열로 바꾸고 세부 창의 사이드바를 위쪽 접이식 영역으로 배치한다. 네이티브 dialog가 키보드 포커스를 창 안에 유지하고 Escape로 닫은 뒤 원래 카드로 돌아간다.

## 공개 정보의 경계

대시보드와 이용 흐름은 로그인 없이 읽기 전용으로 체험할 수 있다. 계정 이름·이메일·토큰·파일명·이력서·보고서·요청 본문은 공개 이벤트에 넣지 않는다. 브라우저의 임의 필드는 서버에서 제거하고 내부 분석 상태를 브라우저 입력으로 확정하지 않는다. 개인 문서 조회와 쓰기 작업은 기존 인증·소유권 검사를 유지한다.

## 검증 기준

서로 다른 작업의 수집·분리, 새 분석 자동 추적, 수동 고정, 실시간 상태 변경, 시연 제외, 요청 실패·중복·순서 역전·재연결·만료, 개인정보 제거를 검증한다. 연결 확인 신호만으로 새 동작이나 진행률을 만들면 안 된다.
