# 개인 포트폴리오 이용 흐름

2026-10-13 개인 Render 배포의 공개 모니터링 기준이다. 이전의 회원 전용·브라우저 탭별 관찰 요구를 대체한다.

## 연결과 관찰 범위

- 기본 ‘실시간 · 전체 이용’은 여러 사용자의 브라우저 동작과 분석 실행 상태를 함께 조회한다. 화면 진입·이력서·공고·로그인·API 요청은 브라우저 관측이며, 워커의 분석 단계는 서버 기록이다. 두 종류를 별도 대상으로 표시하고 상태를 섞지 않는다.
- 브라우저는 허용된 기능명·상태·시간만 중앙 수집기로 전송한다. Redis가 이를 짧게 보관하고, 이용 흐름 화면은 약 1.5초 간격으로 최신 상태를 조회한다. 연결 확인 신호가 과거 동작을 새 활동으로 만들지 않는다.
- 자동 추적은 새 작업을 따라간다. 상세 대상을 고정하면 다른 사용자의 이벤트가 지도를 바꾸지 않는다. 전체 목록에는 여러 대상이 함께 표시된다.
- ‘이 브라우저만’은 같은 출처의 브라우저 채널로 관찰한다. 작업 창에서 연 팝업은 해당 창을 보고, 직접 열린 이용 흐름 화면은 같은 브라우저의 작업 창들을 관찰한다.
- Redis 장애나 조회 실패는 연결 상태에 표시한다. 과거 기록을 현재 실행으로 표시하거나, 누락된 단계를 완료로 추정하지 않는다.

## 표시와 모션

4열 29개 카드로 기존 41개 카드의 기능을 통합했다. 최초 기록·복구·중복 조회에는 과거 애니메이션을 재생하지 않고, 새로 수신한 동작과 상태 변경만 강조한다. 실제 수집된 응답 시간·진행 상태만 표시한다.

시연은 가상 이벤트라는 별도 모드로 구분하며 중앙 수집기로 보내지 않는다. 페이지 기능 안내는 실제 기능 위치에 개별 말풍선으로 표시한다.

## 공개 정보의 경계

대시보드와 이용 흐름은 로그인 없이 읽기 전용으로 체험할 수 있다. 계정 이름·이메일·토큰·파일명·이력서·보고서·요청 본문은 공개 이벤트에 넣지 않는다. 브라우저의 임의 필드는 서버에서 제거하고 내부 분석 상태를 브라우저 입력으로 확정하지 않는다. 개인 문서 조회와 쓰기 작업은 기존 인증·소유권 검사를 유지한다.

## 검증 기준

서로 다른 작업의 수집·분리, 새 분석 자동 추적, 수동 고정, 실시간 상태 변경, 시연 제외, 요청 실패·중복·순서 역전·재연결·만료, 개인정보 제거를 검증한다. 연결 확인 신호만으로 새 동작이나 진행률을 만들면 안 된다.
