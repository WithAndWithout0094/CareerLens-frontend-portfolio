# 코드에서 생성하는 이용 흐름

이용 흐름은 일곱 개의 개요 카드와 단계별 세부 창으로 구성됩니다. 개요 카드의 제목과 묶음은 화면 설명용 메타데이터이며, 상세 카드와 연결은 실행 코드에서 생성합니다. 세부 창의 시연은 가상의 예시이며 서버의 분석·저장·인증 요청을 실행하지 않습니다. 기존 실시간 처리 상태는 실제 관측 기록으로 따로 표시합니다.

## 생성 근거

| 원본 | 자동 반영되는 내용 | 연결 의미 |
| --- | --- | --- |
| `EvaluationEngine.build().get_graph()` | 실제 LangGraph 노드, 시작·종료, 병렬 영역, 조건부 검증·재평가 경로 | `flow`, `conditional` |
| `DOMAIN_WEIGHTS`, `DOMAIN_NAMES`, `CRITERIA` | 평가 영역, 영역별 세부 기준, 실제 결과 필드와 연결 | `contains`, `produces` |
| `app/application/evaluation.py`의 `execute` | 직접 `await measure('단계', ...)` 하는 문서 해석·검색·분석·저장 단계 | 선언된 직접 await 순서 `flow` |
| FastAPI 및 통합 프론트가 사용하는 Flask API decorator | HTTP 메서드·경로, 처리 함수, 응답 모델 | `calls`, `produces` |
| 도달 가능한 Python 처리 함수의 직접 호출 | 같은 모듈 또는 정적으로 import한 함수, 저장소 메서드·테이블 | `calls` |
| Pydantic 모델의 필드 선언 | 요청·응답·평가 결과 필드와 중첩 모델 | `contains` |
| 실제 브라우저 이벤트 허용 목록 및 직접 문자열 관측 호출 | 관측 카드의 존재, 해당 기능의 공개 소스 위치 | 관측 지점의 근거이며 실행 순서를 추측하지 않음 |

`contains`는 구성 관계이고 `calls`는 정적 호출 관계입니다. 둘을 실제 실행 순서나 실제 분석 성공으로 해석하지 않습니다. `conditional`은 가능한 분기이며 시연의 선택은 실제 사용자 실행과 무관합니다. 개요의 좌우 배치는 사용 흐름을 쉽게 읽기 위한 화면 구성입니다.

## 빌드와 배포

```sh
python -m scripts.generate_flow_manifest
```

생성 파일은 `frontend/src/features/activity-flow/generated-manifest.js`입니다. 수동으로 편집하지 않습니다. 기존 파일이 같으면 쓰지 않고, 변경됐으면 임시 파일에서 원자적으로 교체합니다. `sourceDigest`는 생성에 사용한 소스들의 해시입니다. 개인정보나 실행 결과의 해시가 아닙니다.

개인 Render Blueprint와 루트 Blueprint의 빌드 명령에 생성기가 연결되어 있습니다. 기존 Render 서비스에 예전 빌드 명령이 저장된 경우도 처리하도록, 통합 앱은 프론트를 마운트하기 전에 시작 과정에서 한 번 생성합니다. 일반 HTTP 요청마다 생성하지 않습니다. 생성에 실패하면 이전 그래프를 최신인 것처럼 제공하지 않고 시작/빌드가 실패합니다.

생성기는 DB·OpenAI 클라이언트·설정을 초기화하지 않으며, 평가 노드를 실행하지 않습니다. LangGraph는 `EvaluationEngine(None, None).build()`로 구조만 컴파일합니다. 출력에는 공개 경로·함수명·필드명·위치와 설명만 포함합니다. 함수 본문·요청값·비밀번호·환경변수·API 키·이력서·결과 보고서 본문은 포함하지 않습니다.

## 지원 범위와 한계

- 현재 애플리케이션의 정적 경로 선언, 정적으로 해석 가능한 Python 호출, 실제 평가 그래프, 평가 기준, 모델 필드, 직접 `await measure` 단계 변경은 다음 빌드/시작 때 반영됩니다.
- 계산으로 만든 라우트, 런타임 의존성 주입, 동적 함수 선택, 외부 서비스 내부 및 임의 JavaScript 제어 흐름을 모두 추론하는 도구는 아닙니다. 직접 문자열 관측 호출의 위치만 추출하며 템플릿 보간·계산된 인수는 추론하지 않습니다.
- 조건문·루프·콜백 안의 단계에 임의의 선후 관계를 만들지 않습니다. 직접 await 단계는 앞선 단계가 성공해 다음 줄에 도달하는 경우의 순서입니다. 오류·취소의 발생 위치를 이 정적 순서로 단정하지 않습니다.
- 프론트 개발 서버만 독립 실행하면 배포용 생성 명령을 먼저 실행해야 합니다. 통합 앱과 Render 배포는 자동 생성합니다.
- source-only 카드에는 실시간 상태가 없을 수 있습니다. 세부 시연에서는 해당 카드의 타입과 실제 연결 관계를 바탕으로 가상의 상태를 재생합니다. 기존 시연 카탈로그에만 있는 카드는 `demo` 타입과 “시연 전용” 설명을 유지하며, 실제 실행의 근거로 취급하지 않습니다.

## 회귀 검증

`tests/test_flow_manifest.py`는 격리한 소스 복제본에서 실제 경로·응답 필드·평가 기준·그래프 노드를 추가/삭제하고, 그래프 연결을 바꾼 뒤 생성기를 다시 실행해 결과가 바뀌는지 검증합니다. 깨진 graph/schema/관측 참조가 실패하는지도 확인합니다. 테스트는 네트워크·DB·유료 분석을 사용하지 않습니다.
