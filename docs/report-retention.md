# 계정 보고서 보관

회원 분석은 기존 PostgreSQL의 `evaluation_runs` → `match_results` →
`analysis_reports`에 보관됩니다. 보고서 목록과 로그인 후 최신 보고서 복원은
`completed_only=true`로 서버에서 완료·부분 완료를 먼저 고른 뒤 페이지를 나눕니다.
최근 실패·취소 기록 때문에 이전 완료 보고서가 목록에서 밀리지 않습니다.

통합 배포에서 비회원 분석을 로그인 계정에 연결할 때는 기존 PostgreSQL의
`member_guest_reports`에 원문·결과·원래 생성 시각을 먼저 보관합니다.
서버가 검증한 계정 ID에만 연결하며, 같은 보고서 ID의 소유권과 최초 결과는
재시도로 덮어쓰지 않습니다. 영구 보관에 실패하면 연결 성공을 반환하지 않으며
기존 임시 원문은 재시도할 수 있도록 유지합니다.

`002_member_guest_reports.sql`은 기존 스키마나 보고서를 삭제하지 않는 추가
마이그레이션입니다. 개인 Render 시작 스크립트가 이를 멱등 실행합니다.
원래 부트스트랩 스키마와 지문은 변경하지 않습니다.

SQLite는 미연결 비회원 분석의 제한 시간·실행 상태를 보관합니다. 기존 SQLite에
계정 연결된 결과가 남아 있다면 해당 계정으로 목록/상세를 읽을 때만 같은
소유자로 PostgreSQL에 보관합니다. 계정 연결되지 않은 기록을 임의로 배정하지
않습니다. 이미 교체된 Render 인스턴스에서 없어진 SQLite 파일은 이 변경으로
복원할 수 없습니다. 배포 전에 정상적인 소유자 API로 읽을 수 있는 원본은
비공개 위치에 따로 보존해야 합니다.

로그아웃은 브라우저 세션만 비웁니다. 다시 로그인하면 서버 목록을 조회합니다.
명시적인 보고서 삭제 요청만 현재 소유자를 확인한 뒤 기록을 지웁니다.
삭제한 원문은 비우고 소유권 삭제 표지만 남겨, 오래된 SQLite 사본을 다시 읽어도
삭제된 결과를 복원하지 않습니다.
다른 계정의 늦은 응답은 인증 세대 검증으로 폐기합니다.

원래 `RateLimitError`만 기록한 과거 실패는 사용량 소진과 일시 제한을 구분할 수
없습니다. 새 실패는 제공자의 알려진 오류 코드만 분류하여 한도 소진·일시 제한·
접근 설정 오류를 안내합니다. 제공자 원문, 인증키, 개인 문서를 오류로 반환하지
않으며 과금 재시도나 시연 결과로 실제 분석 성공을 대신하지 않습니다.

실제 PostgreSQL 검수는 `tests/test_member_archive_postgres.py`에 별도 구성되어
있습니다. `CAREERLENS_TEST_ARCHIVE_DATABASE_URL`로 명시한 로컬 빈 테스트 DB만
사용하고, 운영용 `DATABASE_URL`은 읽지 않습니다.
